# Internal selection acceptance fixture

WEB-1.3 uses an independently packed `@edit-ac/core` WASM artifact, recovered through production IndexedDB checkpoint, journal, writer and storage lifecycle adapters. The renderer is subscribed before the selection bridge. The fixture exposes selection capture and prepared semantic commands only; ordinary browser input reconciliation is a later gate.

`DOMSelection.capture()` records anchor and focus in their native order, without sorting a backward range. Call it synchronously before preparing a command. Native `selectionchange` also captures keyboard/mouse navigation. Callers may supply left/right affinity independently for each endpoint; the default caret affinity is right. The bridge owns both tokens until the next capture, clear or dispose. Consumers must not retain them beyond that lifetime. `retain()` returns an independently owned range for an asynchronous consumer; later navigation and patch restoration cannot release or redirect it. Dispose the retained handle when finished. Bridge disposal also releases outstanding retained handles.

`toModel`/`toDOM` map UTF-16 Text, hard-break BR, mark-wrapper and block/container/root boundaries. Empty placeholders contribute zero units. Unmapped/noneditable/outside positions and surrogate-interior capture fail explicitly. Element boundaries use mapped positions rather than whole-document text serialization.

After authoritative patches, the bridge resolves its retained anchors and restores native anchor/focus direction after renderer patches. A deleted or unresolvable endpoint clears the owned native selection and returns `stale` with both engine resolutions. No nearby absolute target is substituted. Moving selection outside the root abandons capture and never steals host selection. Dispose the bridge before the renderer and engine.

Run `npm run build --workspace @edit-ac/web`, then `npm run test:browser -- selection`. The runner uses pinned Chromium/Firefox/WebKit. Narrow selection filters must execute at least one case. Real peer insert/structural commands use a second WASM engine and differential update bytes; owner deletion uses a deterministic Yjs peer tombstone admitted by the actual engine and persisted through the production update subscription. Native arrow-key coverage is browser mechanics, not OS IME, screen-reader, mobile or release qualification.
