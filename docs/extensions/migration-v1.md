# Migrate existing low-level consumers

Move feature selection to one `extensions` array without replacing the document, persistence, history or dispatcher. Retain the host's existing recovery identity and immutable asset URLs. Add factories one family at a time and await required readiness. Do not import private `src`/`dist` files. Public advanced module subpaths remain for established consumers.

Legacy Task APIs remain supported with their original capability/byte inventory. `defaultPreset()` expands to an empty extension list with Task editing defaults; `documentPreset()` adds qualified Search/Reorder; `taskPreset` is an explicit compatibility alias. No preset is required and a use-case name never restricts selection. The [configuration contract](configuration-v1.md) defines deterministic legacy/facade conflicts: conflicting selection rejects, rather than silently combining duplicate owners. Do not pass both a low-level adapter and its facade replacement. Preserve public `attachSync` compatibility; managed per-editor collaboration and independently explicit presence do not imply provider work for local siblings.

Required input adapters attach before ready; command-lazy exporters wait for explicit commands. Use feature status and `loadExtension(id)` only to retry supported failed assets (three total attachment attempts); malformed package resolution may require host repair/remount. Failed parser/asset load retains input. Disposal cancels per-editor attachment work even when shared compatible immutable initialization continues for a sibling. Borrowed surface disposal never destroys its host engine/storage owner.

Versioned data can be opaque without presenters/codecs. Preserve unknown types/versions and source fallback. A descriptor version is not the facade API version. Keep the old data until an owning versioned migration exists. New Rust semantics require the canonical owner and qualification; an author callback cannot add a parallel writable model.
