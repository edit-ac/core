# Advanced asset hosting

Most consumers need only the main import and compatible core/web tarballs. Optional Markdown additionally installs `@edit-ac/markdown`; direct browser hosts map its public `@edit-ac/markdown/web` entry. Use the package's conventional immutable URLs or one host `assets.baseURL`/`assets.manifest` override. [The managed loading guide](loading-v1.md) defines exact supported keys, direct-browser and bundler recipes and qualified graphs. Keep versioned URLs compatible; validate WASM MIME, module MIME, CSP and CORS on your host. No broad dynamic barrel or Cargo flag proves bundle separation.

Main imports retain lightweight factories. Optional math/highlight/Markdown and collaboration/provider/presence orchestration activate independently; baseline Yrs/update/local-storage costs remain. Shared compatible initialization does not share cancellation or callback authority. Exporters do not block typing; failed parsing preserves source. Bounded asset retries and late completion are owned by the lifecycle, not copied into beginner extensions. Keep credentials in host callbacks, never package manifests/document data/logs. Heavy or untrusted parsing belongs in an isolated worker; AbortSignal cannot preempt an infinite loop in trusted same-thread code.

PDF export and DOCX import/export browser runtime cells are unavailable here until CNV supplies qualified implementation/asset receipts. PDF import is unsupported by policy. No converter factory is claimed executable. No deployment, native/IME/AT, timing/budget or release qualification follows from these portable examples.
