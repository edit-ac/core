# Shared prepared edit service

`editac_session::edit_service::EditService` owns an existing local-first `Session`. Human UI, scripts and adapters use the same `prepare_commands`, `capture_source` / `prepare_source`, `PreparedEdit::preview`, and `apply` methods. Session admission requires an editor profile with qualified history (v4/v5); older profiles reject before a service handle is available. The companion crate uses the existing Markdown reconciliation crate; the semantic `editac-core` dependency graph is unchanged.

The host grants document access and supplies the current clock, `CachedPermission` and `HostPolicy`. It updates those policy inputs on its serialized owner when authorization changes. The service discovers no credentials and treats caller origin strings as engine origins, never authenticated actor identities. Provenance retention and history origin classification belong to CAP-1.9.

`read` returns a semantic snapshot, opaque observed revision, session state and current capabilities. `observe` compares a previous token and returns a coalesced current snapshot when state changed. This is snapshot observation, not a lossless event stream. Foreign identity tokens reject. The public session accessor is read-only; there is no mutable document accessor or whole-document replacement method.

Command preparation uses the engine's atomic semantic batch planner. Source capture requires exact source plus its owner mapping, then FMT-1.12 prepares a proved reconciliation delta. Unsupported or ambiguous source mappings reject. An overlapping changed source returns exact base/proposed source and current semantic snapshot. A current token does not override stale source mapping. A stale prepared token rejects before commit. Disjoint source changes retain the reconciliation engine's merge policy.

Preparation stages an independent replica to render an immutable semantic preview and leaves the live replica, undo history and store unchanged. IDs created only in the preview are provisional; read the applied snapshot for actual new identities. Opaque prepared edits are single-use and cannot have their revision or delta rewritten. Plans remain tied to their original endpoint replica.

Every preparation, apply, undo and redo checks cached permission/expiry, current host write authority and historical-view policy. Apply also rechecks module capability and resource requirements, so preparing a plan never grants durable permission. Optional image/table/callout/reference commands require explicit host enablement. Source codec registration is explicit and rechecked at apply. Commands are bounded to the lesser of the host cap and engine cap; input accounting includes command identifiers, anchors and tuples via their diagnostic representation. Source input accounts for retained base plus proposed UTF-8 bytes. Engine/parser bounds remain in effect. Undo/redo conservatively retain the greatest resource and module requirements of edits admitted by this service. Revocation blocks history until the host restores the necessary authority. Existing history from before service construction has no qualified requirement envelope and rejects with `UnqualifiedHistory`; opening a restored session provides a fresh qualified history boundary. This guard is independent of the bounded operation records described below.

Revision comparison and engine commit run synchronously within the session's exclusive mutable owner, with no host callback or await between them. The existing journal/outbox records the resulting update before returning `LocalCommit`. `local_receipt` looks up the exact document/writer/sequence/checksum in retained journal/checkpoint coverage; missing records return `None`. It reports the store's local durability capability, never a hosted receipt or remote commit. Post-commit storage failures retain the exact update and freeze admission; `recover` completes ordered persistence before editing resumes. Read-only recovery exports remain available through the session.

Qualification: `cargo test -p editac-session --test edit_service --locked` and the same command with `--features native-store`. The native fixtures require a task-owned `EDITAC_SERVICE_EVIDENCE` directory. The canonical cases use actual engine commands, source reconciliation, memory/fault adapters and SQLite connection reopen; no model calls, production writes or live remote providers are involved.

Operation provenance (CAP-1.9): `apply_as` accepts a `HostOperation` from the trusted host at admission, independently of the prepared client plan. The host must authenticate `HostActor` subjects and choose the origin class itself; the constructor validates a label, not credentials. Do not deserialize request names, replica IDs or document text into this type. Legacy `apply`, undo/redo and received peer entries are explicitly unauthenticated; engine origin strings are retained only as routing tags. `receive_peer` uses the actual journal/engine transport boundary, labels remote integration as replay and never promotes a remote writer into an actor. Duplicate/no-op and rejected requests create no provenance record.

Each semantic mutation records a lifetime-local operation ID, bounded request correlation ID, optional host actor, origin class, untrusted engine origin and exact document/epoch/profile-scoped before/after tokens. Request IDs grant neither authentication nor idempotency; operation IDs restart when a new service is created. Every service apply starts a new engine history group, even when caller origin strings match. Human, other-human, agent, import and replay operations therefore cannot accidentally coalesce as typing; undo/redo remain explicit authorized new changes. This conservative policy does not promise automatic selective agent undo.

Records are volatile endpoint-local sideband metadata, separate from the persisted CRDT and journal, with oldest-first eviction at 256 records or 262,144 accounted bytes. Labels are at most 128 UTF-8 bytes with no controls. Byte accounting covers fixed record fields and owned string capacities (including the local receipt identity); allocator bookkeeping is additional and bounded by the count cap. The API is not a durable audit ledger or cross-client author attestation. Native reopen recovers semantic edits/revision tokens but starts with an empty provenance log and no historical authenticated actor claims. Hosts requiring persistent provenance need a separately qualified retention/authentication adapter. Eviction never deletes document/journal/outbox data.

A semantic commit whose local store acknowledgment fails records `RecoveryRequired` with exact before/after tokens. It is not a local or remote durability receipt. Recovering the same service does not manufacture another operation or silently upgrade that record; exact local receipt lookup remains the durability authority. Native reopen does not recreate volatile records from unauthenticated journal origins.

Provenance qualification: `cargo test -p editac-session --test origins --locked`, also with `--features native-store`; native fixtures require task-owned `EDITAC_ORIGINS_EVIDENCE`. Cases exercise the actual service/history/revision, memory/fault stores, real peer journal delivery and SQLite connection reopen.


Client conformance (CAP-1.10): `fixtures/client-contracts/conformance.tsv` is the shared operation/oracle corpus. `tests/conformance.rs` runs it through the actual headless session with fault storage and optional SQLite. `tests/session-conformance.test.mjs` runs it in Chromium using the actual WASM replica, IndexedDB, public editor command/readonly/keyboard middleware, restore, journal/outbox and sync attachment. It compares every normalized step with the oracle and both native traces. Set a unique absolute `EDITAC_CONFORMANCE_OUTPUT`, run Rust with and without `native-store`, build JS, then run the Node test. Existing local-channel qualification also exercises actual offline multi-tab delivery; hosted transports remain prepared.

The two hosts expose different APIs. A browser host explicitly creates the initialized checkpoint before opening the editor; opening never invents one. Browser failed-transaction recovery exports exact unacknowledged update envelopes before destruction, idempotently settles them into the same journal and reopens through engine-qualified checkpoint/tail restore. Keep that export until settlement succeeds. Native `Session::recover` retries the retained journal entry under the same publication barrier. Neither path upgrades an unsaved export or socket send to a durability receipt. Browser editor readonly protects command and keyboard/history admission; native cached permission protects session command/history admission. Host credentials, policy and clock remain host-owned. Prepared reconnect sends retain pending outbox records and make no remote commit claim.

The minimal `editac-core` build uses no default features and is independently checked through its resolved normal-dependency tree. Session, Markdown, SQLite, terminal/OS UI, MCP, diff presentation and encryption adapters are outside that semantic-core dependency boundary. This qualification proves portable development contracts, not physical-device release, provider quality, CLI delivery or published support.
