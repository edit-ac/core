# Platform spelling and an explicit prepared checker

Use the public configuration path:

```ts
import { createEditor, Spelling } from '@edit-ac/web';
const editor = createEditor(root, { ...Spelling.configure(), assetUrl });
await editor.ready;
```

`platform` preserves the host's explicit/inherited `spellcheck` attribute. It never forces checking on or infers user settings from the DOM property. `off` requests per-surface suppression. `autocorrection: 'inherit' | 'on' | 'off'` is independent; capitalization, prediction, substitutions and keyboard preferences stay with their owners. `platformPreferences` reports the requested policy and `observed: 'unknown'`: HTML attributes do not establish effective spelling, available dictionaries or exclusive suppression. Browser/OS observation belongs to INT-1.14. Coupled native controls remain the native adapters' responsibility; this browser recipe does not approximate them with a global switch.

`Spelling.configure` returns `{platform, extensions}`. Merge its extensions with other configured extensions, and keep the matching platform policy. A missing custom checker or a custom extension paired with platform/off fails before attachment. To change mode, dispose/remount the surface through the existing lifecycle. Disposal restores only SDK-written attributes whose values the host has not subsequently changed. An absent locale is preserved; an explicit locale is a language hint, never a keyboard/dictionary preference override.

For an executable custom example use `preparedSpelling(container)` from `spellcheck.ts`. Its tiny hand-authored dictionary recognizes only `teh`, `recieve`, decomposed `café`, and `wrng` in the declared `en` fixture locale. It is integration data, not language or provider quality. `load` is an explicit trusted callback, lazy on the first eligible changed word; platform/off import no checker runtime, dictionary or worker. No service account, network lookup, startup scan or automatic fallback exists. Unknown/unavailable locales, unavailable checkers and invalid results report diagnostics and retain text. Ignore/learn-word and global dictionary editing are not supplied.

Custom mode requires `overlap: 'allow'` as an explicit host/user presentation choice. It requests `spellcheck=false`, but HTML permits user preferences to override suppression. Exclusive platform/custom presentation is not claimed. Do not select custom mode if overlap is unacceptable. Suggestions use accessible ephemeral groups/buttons outside canonical content; no spelling marks or preferences are synchronized. Hosts can substitute a decoration presenter through `checker.present`, returning an idempotent disposer. Trusted callbacks must be bounded/cooperative; they are not a sandbox. Isolated workers can implement the checker behind the same abortable host interface.

The adapter analyzes local committed input/paste only, with at most a 128 UTF-16 context on each side, 8 matches, 4 active and 4 queued jobs and a 30-second lifetime. Unicode letters/combining marks and internal apostrophes form words; a trailing delimiter is required, boundary-truncated/oversized words are excluded. Code, links, number/underscore/hyphen identifiers, literal origins and active composition are excluded. Block/range limits fail closed. It does not scan a reopened document, remote changes or export. Checkers return at most 5 short replacements; analysis never mutates text. Each presentation holds one current engine-owned target. Acceptance is single-use, checks current text/anchors, generation, permissions, composition and foreign editable focus, then prepares one existing formatting-aware replacement and shared undo unit. Pending work and suggestions are canceled on edit, history, deadline, invalidation or disposal; unrelated edits may rebase targets. Host credentials and learned words never enter document data or logs.

For `teh ` the prepared suggestion is `the`; accepting produces `the ` with the existing formatting policy (the first selected character supplies replacement formatting; adjacent text stays unchanged), one replacement commit, a caret after `the`, and one undo back to the captured original target. Failed/stale/readonly/composing/disposed/foreign-editor acceptance has zero replacement effect. The canonical tests use installed packages and the production engine with prepared checker data. They prove adapter semantics, not OS spelling, IME or accessibility support.
