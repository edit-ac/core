# Browser input and clipboard device protocol

Status: protocol authored; physical-device, real OS IME and screen-reader runs remain unqualified. WEB-1.12 authors this protocol. REL-1.6 and MWB-1.11 own actual browser-device qualification. Native SDK simulator/emulator and hardware tasks are separate future roadmaps; do not execute or claim them from this protocol's automated checks.

Use a locally served packed SDK fixture with the authoritative WASM engine, DOM adapter and IndexedDB storage. Record the exact source/packed JS/WASM hashes, browser build, OS/device model, keyboard/IME layout/version, accessibility tool/version, locale, timezone, input event log and before/after semantic content, selection direction, history and journal receipts. Use prepared content and mocked service transports; no provider calls or live credentials. A missing device, skipped required case or unobserved result stays unchecked.

Required browser matrix: desktop Chromium, Firefox and Safari/WebKit on claimed OS versions; physical iPhone and iPad in Safari; physical Android Chrome with stock keyboard and each additionally claimed vendor keyboard. Include attached hardware keyboards on mobile and portrait/landscape orientation. Browser viewport emulation and constructed ClipboardEvents are regression mechanics only. Record actual clipboard menu/API behavior separately.

For every case, start with `alpha`, a second independent paragraph, a heading, code, a list and a formatted selection containing `😀`, combining accents and RTL text. Clear prior history and record the initial local revision. Execute the listed action through the actual OS input/clipboard/accessibility UI. Check the visible result against the semantic snapshot, undo once, redo once, flush local storage and reopen offline. Keep screenshots/video and any failing event trace. Never edit expected outcomes to hide a failure.
